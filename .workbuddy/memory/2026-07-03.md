## 调研隐藏文件不显示的根因

- 用户反馈：即使用 `sftp` 命令行连接远程主机执行 `ls -a` 也不显示隐藏文件。
- 调研结论：**根因在 SFTP 服务端/中间代理层，不是客户端代码问题**。
  - SFTP 协议的 `SSH_FXP_READDIR` 操作返回目录中所有文件，协议层面没有"隐藏文件"概念。
  - 应用后端 `sftp.readdir()` 直接透传服务端返回的结果，没有任何过滤。
  - 前端 `visibleFiles` 的过滤逻辑正确（单元测试验证）。
  - 如果 `sftp` 命令行 `ls -a` 也不显示隐藏文件，说明 SFTP 服务端或 JumpServer 代理在 `readdir` 响应中过滤了 dot 文件。
  - JumpServer 的 SFTP 服务（端口 2222）是自实现代理，某些版本会过滤 dot 文件。
- 添加了调试日志：在 `ssh:sftp:list` handler 中调用 `homeDebug` 记录 `sftp.readdir()` 返回的原始文件名列表和 dot 文件数量，写入 `~/.chaterm-home-debug.log`。
- 验证：`npm run typecheck` 通过；lint/prettier 通过。

## 实现 SSH exec fallback 方案

- 文件：`src/main/ssh/sftpTransfer.ts`。
- 核心逻辑：在 `ssh:sftp:list` 中，当 `sftp.readdir()` 返回的目录项里没有 dot 文件时，通过底层 SSH 连接执行 `ls -a -1 -- <path>` 获取完整文件名列表，再用 `sftp.stat()` 补齐缺失条目的元数据并合并返回。
- 新增/导出辅助函数：
  - `findSshConnForSftp(id)`：根据连接 ID 找到对应的 SSH Client，支持普通 SSH 连接和 JumpServer compound-username SFTP 连接（`sftpOwnedJumpServerConnections`）。
  - `execListDirViaSsh(conn, path)`：在 SSH 连接上执行 `ls -a -1`，解析 stdout 为文件名数组。
  - `wrapSftpAttrs(st)`：将 ssh2 原始 stat 对象包装为带 `isDirectory()`/`isSymbolicLink()`/`isFile()` 方法的对象。
  - `enrichReaddirWithExecFallback(conn, sftp, path, list)`：合并 exec 得到的名字与 readdir 结果，stat 缺失条目。
  - `readSftpDirWithFallback(sftp, path, id, label)`：统一封装 readdir + fallback 逻辑。
  - `formatSftpList(list, path)`：将 readdir 结果格式化为前端需要的对象。
- 重构 `ssh:sftp:list` handler：去掉重复的 readdir/映射代码，改用 `readSftpDirWithFallback` 和 `formatSftpList`。
- 新增测试：`src/main/ssh/__tests__/sftpTransfer.list-fallback.test.ts`，覆盖 exec 解析、wrapSftpAttrs、合并缺失隐藏文件、触发 fallback 条件、前缀匹配查找 SSH 连接等场景。
